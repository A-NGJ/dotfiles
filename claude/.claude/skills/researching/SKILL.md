# Research

## Workflow

1. Interview relentlessly before investigating. Ask about motivation, prior attempts, constraints, and success criteria — 1-2 questions at a time, adapting to answers. Stop when you have answers to all four.

2. Reflect back a concise problem statement and get confirmation before investigating.

3. Investigate, scaling effort to the question, until the confirmed problem statement is answered - broad questions warrant parallel investigation across multiple sources or codebase areas.

4. Checkpoint when investigation fans out across multiple sources or areas: present the findings so far and the direction you intend to take next, then continue once the user confirms or redirects. If findings raise new questions, ask them here.

5. Offer to save the research; if accepted, write it per `templates/research.md`, following its filing rules for location, naming and status.

## Evidence

- Read all mentioned files fully before investigating further.
- Prefer authoritative sources - project README, official docs, release notes; flag findings drawn from blog posts or forum threads as such.
- Cite the source of every finding: file:line for codebase claims, URL or quoted documentation for external claims.
- Facts first, opinions when warranted
